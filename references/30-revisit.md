# 30 · 다시 부를 때 (모드 ②)

## R0 집계 — 질문 전에 AI 혼자

`docs/ops-os/log.md` 에서 가장 최근 운영중 버전의 `shipped_at` 이후 줄만 센다. 평균은 **기준선과 같은 단위**로 낸다.

| 값 | 계산 |
|---|---|
| 쓴 횟수 | 「안 씀」 칸이 비어 있는 줄 |
| 일이 생긴 횟수 | 쓴 횟수 + 「안 씀」 줄 (이유가 "일이 없었음"이면 빼기) |
| 쓴 비율 | 쓴 횟수 ÷ 일이 생긴 횟수 |
| 평균 분/주 | `cycle` 이 매일·주 단위면 「걸린 분」 합 ÷ 경과 주. 매월·분기·반기면 **한 주기 합 ÷ 주기 주 수**(매월 4.3 · 분기 13 · 반기 26). 한 주기가 안 지났으면 "추정" |
| 기준선 대비 | `baseline_min_per_week` − 평균 분/주 |
| 남은 손일 (분/주) | 「손으로 한 부분」 칸의 분 합, 위와 같은 방식으로 환산 |
| 사람만 몫 | 남은 손일 중 태그가 붙은 분 ÷ 남은 손일. **단, 정보성 확인 메시지의 `[게시·발송]` 은 `14-human-only.md` C-2 조건으로 v2 에서 자동화할 수 있으니 빼고 센다.** 광고성 `[게시·발송]` 과 `[인증]` `[서명]` `[송금]` `[제출·신고]` 는 넣는다 |
| 준비물 틀림 | 「손으로 한 부분」 칸에 "(준비물 틀림)" 이 붙은 줄 수 |
| 안 씀 이유 | 까먹음 / 손으로가 더 빠름 / 일이 없었음 / 기타 — 횟수 |
| 실수 | 「고친 것·실수」 칸 |

- log 가 비었으면 R1 에서 기억으로 다시 만들고 모든 숫자에 "추정".
- 집계는 log.md 「주간 합계」 절에 채운다. AI 가 log 에 쓰는 곳은 이 절뿐이다.

## 질문 (한 번에 하나)

- **R1** "기록으로는 N번 썼고 일이 M번 생겼어요. 맞나요?" — 맞음 / 더 썼는데 안 적음 / 덜 씀. log 가 없으면 열린 질문 "v1 을 몇 번 쓴 것 같나요?"
- **R2** (쓴 비율이 100% 가 아닐 때만) "안 쓴 날 가장 큰 이유는?" — log 선택지와 같음
- **R3** "그 일에서 아직 손으로 하는 부분은?" — v1-plan §3 「후」 단계표에서 사람·손 단계 다중 선택 + "문구를 매번 고친다" + "없음"
- **R4** 판정을 보여 주고 확인 — 추천이 첫 번째, 다른 판정 둘, "이번엔 유지"

## 판정 규칙 — 위에서부터 첫 번째로 맞는 것

1. **v1.1 고치기** — 쓴 비율 < 50%, 또는 준비물 틀림 2회 이상, 또는 "손으로가 더 빠름" 2회 이상. **다음 단계로 가지 않는다.** 고칠 곳: 준비물 정확도 · 버튼 위치 · 알림 시점.
2. **v3 연결** — **서로 다른 일(task)** 의 운영중 버전이 2개 이상(`대체됨` 제외), 각각 log 2주(월 단위 일이면 두 주기) 이상, 쓴 비율 ≥ 50%.
3. **깊게** — 남은 손일 ≥ 기준선의 30% **이고** 사람만 몫 < 70%.
   - 다음에 자동화할 단계 = 남은 손일 중 태그가 없는(또는 정보성 발송인) 가장 긴 단계.
   - 예: "문구를 거의 안 고치고 붙여 넣어 보냄" → 정보성 자동 발송 / 수동 실행 → 예약 실행 / 복사 → 공식 연결.
   - 승인이 필요하면(알림톡 L-C6, 발급 API L-A1) 이번 vN 은 "준비 신청 체크리스트 + 승인 전까지 쓰는 임시 경로"로 쓴다.
4. **넓게** — 사람만 몫 ≥ 70%, 또는 남은 손일 < 기준선의 20%. `00-map.md` 를 다시 채점하고(바뀐 사실 반영) 다음 순위 일로 간다. 새 일도 v1 규칙(일 하나 · 반자동 · 하루)과 게이트 G1~G5 를 그대로 따른다.
5. **유지** — 나머지 (남은 손일이 기준선의 20~30% 이고 사람만 몫 < 70%). log 만 계속 쓰고 2주(또는 한 주기) 뒤 다시.

## 버전 이름과 status

| 판정 | 파일 | `direction` | 이전 버전 status |
|---|---|---|---|
| v1.1 고치기 | `v1.1-plan.md` | v1.1 | 새 버전이 운영을 시작하면 `대체됨` |
| 깊게 | 다음 번호 `v2-plan.md`, `v3-plan.md` … | 깊게 | 새 버전이 운영을 시작하면 `대체됨` |
| 넓게 | 다음 번호 | 넓게 | `운영중` 그대로 (다른 일이라서) |
| v3 연결 | `connect-plan.md` (`version: connect`) — `task` 에 묶는 일 번호 목록 | 연결 | 묶인 버전들 `운영중` 그대로 |

파일 번호는 순서일 뿐이고, "v3 = 연결"은 개념 이름이다. 넓게를 두 번 해서 `v3-plan.md` 가 생겨도 연결 기획안과 겹치지 않게 연결은 항상 `connect-plan.md` 로 쓴다.
