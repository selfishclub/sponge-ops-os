# 30 · 다시 부를 때 (모드 ②)

## R0 집계 — 질문 전에 AI 혼자

`docs/ops-os/log.md` 에서 가장 최근 운영중 버전의 `shipped_at` 이후 줄만 센다.

| 값 | 계산 |
|---|---|
| 쓴 횟수 | 「건너뜀(이유)」 칸이 비어 있는 줄 |
| 일이 생긴 횟수 | 쓴 횟수 + 건너뜀 줄 (이유가 "일이 없었음"인 줄은 빼기) |
| 쓴 비율 | 쓴 횟수 ÷ 일이 생긴 횟수 |
| 평균 분/주 | 「걸린 분」 합 ÷ 경과 주. 7일 미만이면 경과일로 환산하고 "추정" |
| 기준선 대비 | `baseline_min_per_week` − 평균 분/주 |
| 남은 손일 | 「손으로 한 부분」 칸에 적힌 분의 주당 합 |
| 건너뜀 이유 | 까먹음 / 준비물이 틀림 / 손으로가 더 빠름 / 일이 없었음 / 기타 — 횟수 |
| 실수 | 「고친 것·실수」 칸 |

- log 가 비었으면 R1 에서 기억으로 다시 만들고 모든 숫자에 "추정".
- 집계는 log.md 「주간 합계」 절에 채운다. AI 가 log 에 쓰는 곳은 이 절뿐이다.

## 질문 (한 번에 하나)

- **R1** "기록으로는 N번 썼고 일이 M번 생겼어요. 맞나요?" — 맞음 / 더 썼는데 안 적음 / 덜 씀. log 가 없으면 열린 질문 "v1 을 몇 번 쓴 것 같나요?"
- **R2** (쓴 비율이 100% 가 아닐 때만) "안 쓴 날 가장 큰 이유는?" — log 선택지와 같음
- **R3** "그 일에서 아직 손으로 하는 부분은?" — v1-plan §3 「후」 단계표에서 사람·손 단계 다중 선택 + "문구를 매번 고친다" + "없음"
- **R4** 판정을 보여 주고 확인 — 추천이 첫 번째, 다른 판정 둘, "이번엔 유지"

## 판정 규칙 — 위에서부터 첫 번째로 맞는 것

1. **v1.1 고치기** — 쓴 비율 < 50%, 또는 "준비물이 틀림" 2회 이상, 또는 "손으로가 더 빠름" 2회 이상. **다음 단계로 가지 않는다.** 고칠 곳: 준비물 정확도 · 버튼 위치 · 알림 시점.
2. **v3 연결** — 운영중 버전 2개 이상, 각각 log 2주 이상, 쓴 비율 ≥ 50%.
3. **깊게** — 같은 일의 남은 손일 ≥ 기준선의 30% 이고, 다음 자동화 단계가 사람만 하는 단계가 아니다.
   - 예: "문구를 거의 안 고치고 보냄" → 정보성 자동 발송 (`14-human-only.md` C 조건) / 수동 실행 → 예약 실행 / 복사 붙여넣기 → 공식 연결.
   - 승인이 필요하면(알림톡 L-C6, 발급 API L-A1) 이번 vN 은 "준비 신청 체크리스트 + 승인 전까지 쓰는 임시 경로"로 쓴다.
4. **넓게** — 남은 손일이 대부분 사람만 하는 단계이거나 기준선의 20% 미만. `00-map.md` 를 다시 채점하고(바뀐 사실 반영) 다음 순위 일로 간다. 새 일도 v1 규칙(일 하나 · 반자동 · 하루)을 그대로 따른다.
5. **유지** — 위에 안 걸림 (예: 남은 손일 20~30%, 쓴 비율 좋음). log 만 계속 쓰고 2주 뒤 다시.

## 버전 이름

| 판정 | 파일 | `direction` |
|---|---|---|
| v1.1 고치기 | `v1.1-plan.md` | v1.1 |
| 깊게 · 넓게 | 다음 정수 `v2-plan.md` | 깊게 / 넓게 |
| v3 연결 | `v3-plan.md` — `task` 에 묶는 일 번호 목록 | 연결 |

넓게로 새 일을 시작해도 번호는 이어진다(v2). `task` 에 지도 #번호가 들어가서 어떤 일인지 구분된다.

## v3 연결 — 한 화면

- 「오늘 할 운영」 목록: 일마다 준비된 건수 · 버튼 · 마지막 실행 시각.
- 칸은 대개 4(어드민 한 페이지)나 2(시트 대시보드 탭). 형태가 섞여 있으면 각 일은 그대로 두고 **보는 화면만** 하나로 만든다.
- 이전 버전의 status 는 `운영중` 으로 둔다.
